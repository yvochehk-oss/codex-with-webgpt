Why it matters

不是“问一次 AI”，而是把协作过程变得可追踪

这个 skill 关注的是会话身份、阶段边界和证据核验，让 Codex 与 WebGPT 的分工不会停留在一句“已经完成”。

01

不操作错会话

使用用户给出的完整 ChatGPT 会话 URL，进入或选中确切对话，并核对实际 URL；不会只凭会话标题或当前活动页面猜测目标。

02

不把旧回复当新结果

发送阶段任务前记录当前消息状态，之后确认本次新用户消息与其后的新助手回合。发送状态不明时先检查，不盲目重发可能产生副作用的操作。

03

不把文字声称当完成证据

Codex 独立核验可以观察到的结果：文件看实际内容，提交看真实 SHA，测试看退出码和关键日志，外部操作看实际状态。

Five-step loop

五步协作闭环

网页端负责当前阶段能够完成的工作，Codex 负责组织、读取、验证与推进。能力始终受真实工具和权限约束。

锁定目标会话

取得完整会话 URL，精确进入对应 ChatGPT 对话并确认已登录、可读、可发送。

组织阶段任务

Codex 将目标缩成一个可核验阶段，明确必要输入、允许范围、交付物和证据要求。

WebGPT 处理本阶段

WebGPT 只在当前会话实际拥有的工具与授权范围内工作；无法完成或无法验证时应明确说明。

读取新的完整回合

Codex 等待本次用户消息之后的新助手回复完成，旧回复、错误页面和仍在生成的片段都不算结果。

核验证据再推进

Codex 检查真实结果，区分已证实与未验证部分，再决定完成、补证、修正或进入下一阶段。

WebGPT 处理 Codex 本轮明确交给它、且当前会话实际能力支持的阶段任务。
⇄
Codex 拆分任务、操作内置浏览器、读取新回复，并在真实环境里独立核验结果。
Workflow board

协作状态看板

这是静态的方法论看板，不是项目 Issue、发布进度或 Roadmap。它展示一轮可靠协作应该经过哪些状态。

① 阶段任务 Scope
GOAL 明确一个具体结果

把大任务缩成这一轮可以判断完成与否的目标。

BOUNDARY 限定允许操作范围

明确仓库、分支、文件、外部操作和不可触碰的边界。

EVIDENCE 先定义交付证据

要求网页端报告实际完成事项、证据与无法验证的部分。

② WebGPT 回合 Turn
TARGET 精确目标会话

以完整 URL 绑定对话，而不是模糊寻找“看起来像”的页面。

IDENTITY 确认新用户消息

发送后检查页面确实出现本轮阶段任务，避免把未知发送状态当成功。

RESPONSE 只读取新的完整回复

没有新回合、回复仍在生成或会话不匹配时，不把内容用于后续决策。

③ Codex 验证 Verify
FILES 查看真实文件

网页回复说“已修改”只是线索，Codex 仍要检查实际内容与允许范围。

GIT / TESTS 核对 SHA 与退出码

涉及 Git 时看真实提交；涉及测试时看执行结果和关键日志。

DECISION 区分已证实与未验证

证据充分再推进；缺证据则补证或修正，而不是把推测包装成完成。

Boundaries first

能力边界写在页面上，而不是藏在脚注里

可靠协作的前提，是不把本机权限、网页登录和网页端工具连接混为一谈。

它实际做什么

  • 只使用 Codex 内置浏览器与 Computer Use 操作用户指定的 ChatGPT 会话。
  • 把用户目标拆成一个个有范围、有交付物、有证据要求的阶段任务。
  • 检查新消息与新助手回合，遇到状态不明时先核对现状再决定是否重试。
  • 由 Codex 对文件、提交、测试和其他可观察结果做独立核验。
  • 需要 GitHub 协作时，可在用户明确范围内结合本机 GitHub CLI 或网页端实际可用的 GitHub 连接。

它不会擅自假设什么

  • 不使用 Safari、外部 Chrome、CDP、AppleScript 或浏览器扩展作为该 skill 的工作方式。
  • 不因为本机已经登录 gh，就假设 ChatGPT 网页端也获得 GitHub 访问权限。
  • 不把 WebGPT 的文字回复直接视为文件、提交、测试或外部操作已经完成。
  • 不在会话不匹配、发送状态未知或回复不完整时盲目推进可能有副作用的步骤。
  • 不要求用户把账号密码、验证码、Cookie 或令牌发送给 Codex。

三种状态，三套权限

Codex 本机 GitHub CLI ≠ ChatGPT 网页登录 ≠ ChatGPT 会话中的 GitHub 连接

只有当前阶段真实存在的工具和授权才算能力。网页端如果要读写 GitHub，需要该会话本身具备相应连接与仓库权限；本机 gh 登录不会替网页端授权。

Quick start

三步开始协作

  1. 将仓库中的 SKILL.md 放到 ~/.codex/skills/codex-with-webgpt/SKILL.md，已安装时用新版本覆盖。
  2. 确认 Codex 能使用 Computer Use 控制内置浏览器，在其中登录 ChatGPT，并取得目标对话的完整 https://chatgpt.com/c/<conversation-id> 地址。
  3. 把任务、目标会话和允许操作范围告诉 Codex；需要 GitHub 协作时，再明确目标仓库与允许的 Git 操作。
